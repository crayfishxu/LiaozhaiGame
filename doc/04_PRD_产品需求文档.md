## 1. 背景与目标

### 1.1 背景

| 事实 | 数据 |
|------|------|
| Roguelike 赛道规模（2025） | 中国约 123.6 亿元，同比 +21.3% |
| 卡牌肉鸽在小游戏平台已被验证 | 《一步两步》2025 年 H5 收入 6.23 亿，占飞鱼科技营收 76.9% |
| 纯 IAA 路径已验证 | 《看谁能打过》纯 IAA 起家，出海后月流水 6761 万 |
| 小团队可行性已验证 | 《赵云与阿斗》3–5 人团队，微信抖音双榜第一，好评 95.6% |
| 聊斋题材现状 | 竞品众多（倩女幽魂/聊斋搜神记/神都夜行录等），但**全部是抽卡+数值养成，无一款卡牌构筑 Roguelike** |

**机会点：题材不稀缺，玩法组合稀缺。**

### 1.2 产品定位

> 一款**聊斋美人题材**的卡牌构筑 Roguelike 单机手游。纯单机、离线可玩、竖屏单手操作，单局 8–15 分钟，免费下载 + 广告变现。

### 1.3 版本目标

| 目标 | 指标 | 说明 |
|------|------|------|
| 验证核心玩法 | 次日留存 ≥ 35% | 低于此值说明循环有问题 |
| 验证上手门槛 | 首局完成率 ≥ 80% | 教学与难度是否合理 |
| 验证上头程度 | 人均日局数 ≥ 2.0 | 是否具备重复游玩动机 |
| 验证变现能力 | 广告观看率 ≥ 45% | 广告点位设计是否成立 |
| 控制体量 | MVP 4–5 人 4 个月 | 范围不失控 |

### 1.4 成功指标（上线 3 个月）

| 指标 | 目标值 |
|------|--------|
| 次日留存 | ≥ 40% |
| 7 日留存 | ≥ 15% |
| 30 日留存 | ≥ 6% |
| 人均单日时长 | ≥ 25 分钟 |
| 完整通关率 | 8–15% |
| 人均日激励视频 | 4–6 次 |
| 主观好评率 | ≥ 80% |

## 2. 目标用户与场景

### 2.1 用户分层

| 层级 | 画像 | 占比 | 核心诉求 |
|------|------|------|----------|
| 核心层 | 玩过杀戮尖塔/月圆之夜 | 15% | 构筑深度、流派广度、挑战性 |
| 中间层 | 玩过卡牌但非硬核 | 35% | 易上手、有成长感、不逼氪 |
| 泛用户 | 小游戏入口，碎片时间 | 50% | 3 秒懂、单局短、无压力 |

### 2.2 核心场景

| 场景 | 时长 | 需求 |
|------|------|------|
| 通勤地铁 | 5–10 分钟 | 打 1 局，可随时中断 |
| 午休 | 15–20 分钟 | 打 1–2 局 |
| 睡前躺床 | 10 分钟 | 单手竖屏，可暂停 |
| 工位摸鱼 | 不限 | 随时退出，进度保留 |

| 地图 | 3 层分支地图，6 类节点 | P0 |
| 旧物 | 40 个 | P0 |
| 敌人 | 第 1 层完整（4 普通 + 1 精英 + 1 Boss）；第 2、3 层各 1 Boss + 2 普通 | P0 |

| 局外 | 悟道点、卡池解锁 | P1 |

| 不做项 | 原因 |

| 内购 | 本版纯 IAA |
| 药水系统 | 待定项（见 GDD 12 章） |
| 卡牌升级 | 待定项 |

## 4. 系统需求

> **编号规则**：`REQ-{模块}-{序号}`
> **EARS 类型标注**：`[U]` Ubiquitous ｜ `[E]` Event-driven ｜ `[W]` Unwanted ｜ `[S]` State-driven ｜ `[O]` Optional

### 4.1 战斗系统（BAT）

| 编号 | 类型 | 需求描述 |
|------|------|----------|
| REQ-BAT-001 | [U] | 系统应始终保证战斗为回合制，玩家与敌人交替行动，不存在实时操作。 |
| REQ-BAT-002 | [E] | 当玩家回合开始时，系统应依次执行：障清零 → 反伤清零 → 心力回满 → 结算自身祟毒 → 触发回合开始效果 → 抽 5 张牌 → 刷新敌人意图。 |
| REQ-BAT-003 | [E] | 当玩家打出卡牌时，系统应立即扣除对应心力、结算卡牌当前面的效果、将该牌翻面、并置入弃牌堆。 |
| REQ-BAT-004 | [E] | 当玩家结束回合时，系统应弃置全部手牌（保留类除外），然后按从左到右顺序依次执行敌人行动。 |
| REQ-BAT-005 | [E] | 当抽牌堆为空且弃牌堆非空时，系统应将弃牌堆洗牌后作为新抽牌堆。 |
| REQ-BAT-006 | [S] | 当玩家心力不足时，系统应将该玩家手牌中费用高于剩余心力的卡牌置为不可用状态（视觉降透明度且不可点击）。 |
| REQ-BAT-007 | [W] | 若玩家魂火降至 0 或以下，则系统应立即结束本局并进入失败结算界面。 |
| REQ-BAT-008 | [W] | 若全部敌人魂火降至 0，则系统应结束战斗并进入奖励流程。 |
| REQ-BAT-009 | [S] | 当目标存在障时，系统应先扣除障值，溢出部分才扣除魂火。 |
| REQ-BAT-010 | [S] | 当目标处于祟弱状态时，系统应将其造成的伤害乘以 0.75 并向下取整。 |
| REQ-BAT-011 | [E] | 当玩家受到实际伤害（扣魂火 > 0）时，系统应给予 2 点怨气。 |
| REQ-BAT-012 | [U] | 系统应始终在玩家回合内展示每个敌人的下一步意图（攻击/防御/施毒/强化/缠绕）。 |

### 4.2 卡牌系统（CRD）

| 编号 | 类型 | 需求描述 |
|------|------|----------|
| REQ-CRD-001 | [U] | 系统应始终为每张情念维护「显相」与「本相」两组独立的效果数据。 |
| REQ-CRD-002 | [E] | 当一张牌被打出时，系统应结算其**当前面**的效果，随后翻面，使下次抽到此牌时呈现另一面。 |
| REQ-CRD-003 | [U] | 系统应始终保证翻面不改变卡牌的费用、类型、目标类型与稀有度，仅切换效果。 |
| REQ-CRD-004 | [S] | 当手牌数量超过 10 张时，系统应停止抽牌。 |
| REQ-CRD-005 | [W] | 若牌组已达 40 张上限，则系统应禁止玩家再添加新卡牌，并给出提示。 |
| REQ-CRD-006 | [S] | 当卡牌带有「消耗」关键词时，系统应在打出后将其移出本局，不进入弃牌堆。 |
| REQ-CRD-007 | [S] | 当卡牌带有「保留」关键词时，系统应在回合结束时不移入弃牌堆。 |
| REQ-CRD-008 | [S] | 当战斗中首次打出某张牌时，系统应使用其默认面（MVP 阶段所有初始牌组默认为显相）。 |
| REQ-CRD-009 | [W] | 若手牌中存在「祟」类牌，则系统应将其标记为不可打出（点击无响应且视觉降透明）。 |

### 4.3 地图系统（MAP）

| 编号 | 类型 | 需求描述 |
|------|------|----------|
| REQ-MAP-001 | [U] | 系统应始终在三层地图中采用自下而上的单向推进结构，不允许回头或跨行移动。 |
| REQ-MAP-002 | [E] | 当进入一层地图时，系统应依据层配置生成节点骨架、填充类型、生成连线，并完成 11 项硬性约束校验。 |
| REQ-MAP-003 | [U] | 系统应始终保证第 1 行全部为战斗节点。 |
| REQ-MAP-004 | [U] | 系统应始终保证 Boss 前一行仅有一个休息节点。 |
| REQ-MAP-005 | [U] | 系统应始终保证精英节点不出现在前 2 行，商店节点不出现在最后 2 行。 |
| REQ-MAP-006 | [S] | 当玩家处于某节点时，系统应仅允许点击该节点连出的 1–2 个后继节点，其余节点显示为不可进入。 |
| REQ-MAP-007 | [W] | 若生成的路径数量少于层配置要求（第 1、2 层 ≥4，第 3 层 ≥3），则系统应重新生成，最多重试 10 次。 |
| REQ-MAP-008 | [U] | 系统应始终保证地图中不存在孤立节点，任何节点均可从起点到达且可通向 Boss。 |
| REQ-MAP-009 | [E] | 当玩家完成节点内容后，系统应返回地图并更新可达节点状态。 |
| REQ-MAP-010 | [O] | 系统应支持通过种子复现同一张地图，用于测试与问题复现。 |

### 4.4 旧物系统（REL）

| 编号 | 类型 | 需求描述 |
|------|------|----------|
| REQ-REL-001 | [E] | 当玩家击败精英或 Boss 时，系统应提供 3 个随机旧物供选择 1 个（必得）。 |
| REQ-REL-002 | [S] | 当玩家已持有 8 个旧物时，系统应在获得新物品前弹出替换界面，允许放弃新旧物。 |
| REQ-REL-003 | [U] | 系统应始终保证同一局内不出现重复旧物。 |
| REQ-REL-004 | [E] | 当触发条件满足时，系统应通过统一事件总线通知旧物系统，不得在卡牌逻辑中硬编码旧物判断。 |
| REQ-REL-005 | [S] | 当多个旧物同时触发时，系统应按获取顺序依次结算。 |
| REQ-REL-006 | [S] | 当百分比增益叠加时，系统应采用加法叠加，最终伤害倍率不超过 2.5 倍。 |
| REQ-REL-007 | [S] | 当玩家持有诅咒类旧物时，系统应在每回合/每场战斗按定义结算其代价。 |
| REQ-REL-008 | [W] | 若旧物增益导致伤害超出 2.5 倍上限，则系统应截断至上限值而非继续累加。 |

### 4.5 局外成长（META）

| 编号 | 类型 | 需求描述 |
|------|------|----------|
| REQ-META-001 | [E] | 当一局结束（无论胜负）时，系统应按本局表现结算悟道点并累加至账户。 |
| REQ-META-002 | [S] | 系统应仅通过悟道点解锁「新卡牌进入卡池」「新妖灵」「新初始牌组」，不得解锁任何直接数值提升。 |
| REQ-META-003 | [W] | 若玩家尝试解锁会破坏平衡的内容（如永久攻击力加成），则系统不应提供该选项。 |
| REQ-META-004 | [E] | 当玩家首次通关某难度时，系统应自动解锁下一难度层级。 |

### 4.6 广告与商业化（ADS）

| 编号 | 类型 | 需求描述 |
|------|------|----------|
| REQ-ADS-001 | [E] | 当玩家魂火归零时，系统应提供 1 次「观看广告复活」机会（每局 1 次，回复 30% 魂火上限）。 |
| REQ-ADS-002 | [E] | 当进入结算界面时，系统应提供「观看广告双倍悟道点」选项（每日上限 5 次）。 |
| REQ-ADS-003 | [E] | 当进入情念三选一奖励时，系统应提供「观看广告重抽」选项（每局 2 次）。 |
| REQ-ADS-004 | [S] | 系统应限制单用户每日激励视频总次数不超过 8 次。 |
| REQ-ADS-005 | [W] | 若玩家进入游戏 30 秒内，则系统不得展示任何插屏或横幅广告。 |
| REQ-ADS-006 | [W] | 若广告加载失败或用户中途关闭，则系统应正常发放原奖励（不可用时降级为无奖励继续流程），不得阻塞游戏。 |
| REQ-ADS-007 | [U] | 系统应始终保证所有激励视频均由玩家主动点击触发，不存在强制观看。 |
| REQ-ADS-008 | [U] | 系统应始终保证广告奖励只影响「资源获取效率」，不影响卡牌强度与掉落概率。 |

### 4.7 存档与中断（SAVE）

| 编号 | 类型 | 需求描述 |
|------|------|----------|
| REQ-SAVE-001 | [E] | 当玩家退出游戏时，系统应保存当前心劫进度（地图状态、牌组、旧物、魂火、层数）。 |
| REQ-SAVE-002 | [E] | 当玩家重新进入游戏且存在未完成的心劫时，系统应提示继续或放弃。 |
| REQ-SAVE-003 | [W] | 若存档损坏或版本不兼容，则系统应提示并清除该存档，保证可正常开始新局。 |
| REQ-SAVE-004 | [U] | 系统应始终采用本地存档，不依赖网络。 |

### 4.8 新手引导（GUIDE）

| 编号 | 类型 | 需求描述 |
|------|------|----------|
| REQ-GUIDE-001 | [E] | 当玩家首次进入战斗时，系统应以高亮+文字提示引导依次完成：出牌 → 观察敌人意图 → 结束回合。 |
| REQ-GUIDE-002 | [E] | 当玩家首次打出任意卡牌时，系统应提示「这张牌翻面了，下次抽到是另一面」。 |
| REQ-GUIDE-003 | [S] | 引导总时长应不超过 3 分钟，且全程不阻断操作超过 2 秒。 |
| REQ-GUIDE-004 | [O] | 系统应提供「跳过引导」选项，跳过后可在设置中重新查看。 |

## 7. 数据埋点

### 7.1 核心事件

| 事件名 | 触发时机 | 关键参数 |
|--------|----------|----------|
| `run_start` | 开始一局 | 妖灵 id、种子、难度层级 |
| `run_end` | 一局结束 | 结果、层数、时长、种子、死亡原因 |
| `battle_start` | 进入战斗 | 节点类型、敌人列表、牌组构成、旧物列表 |
| `battle_end` | 战斗结束 | 结果、回合数、剩余魂火、造成伤害、承受伤害 |
| `card_play` | 每次出牌 | 卡牌 id、当前面（显/本）、回合数、剩余心力 |
| `card_flip` | 卡牌翻面 | 卡牌 id、翻向前 |
| `card_choose` | 奖励选择 | 3 个选项、实际选择、是否重抽 |
| `relic_get` | 获得旧物 | 旧物 id、稀有度、来源 |
| `relic_trigger` | 旧物触发 | 旧物 id、触发类型 |
| `node_enter` | 进入节点 | 节点类型、层、行、当前魂火 |
| `map_generate` | 地图生成 | 层、生成耗时、重试次数、路径数 |
| `ad_show` | 广告展示 | 点位、触发场景 |
| `ad_complete` | 广告完成 | 点位、奖励内容、是否成功 |

### 7.2 关键分析口径

| 分析目的 | 计算方式 |
|----------|----------|
| 显相/本相使用比 | `card_play` 中 side=ben 的占比 |
| 流派识别 | 按卡牌 id 归类到幽怨流/情丝流，占比 > 60% 判定为该流派 |
| 难度曲线 | 各层死亡率的分布 |
| 旧物强度 | 按旧物 id 分组，比较持有该旧物的通关率 |
| 广告效率 | 各点位的 `ad_complete / ad_show` |

## 8. 验收标准

### 8.1 功能验收

| # | 验收项 | 通过标准 | 对应需求 |
|---|--------|----------|----------|
| 1 | 回合流程 | 按 BAT-002 顺序完整执行，无遗漏步骤 | BAT-002~005 |
| 2 | 翻面机制 | 每张牌打出后正确翻面，下次抽到呈现另一面 | CRD-001~003 |
| 3 | 伤害计算 | 障抵扣、祟弱系数、旧物加值、2.5 倍截断全部正确 | BAT-009~010、REL-006 |
| 4 | 地图生成 | 1000 次生成中 11 项硬性约束违反次数 = 0 | MAP-003~008 |
| 5 | 地图连通性 | 1000 次生成中无孤立节点、无死路 | MAP-008 |
| 6 | 旧物触发 | 40 个旧物在对应时机 100% 触发，无误触 | REL-004~005 |
| 7 | 旧物上限 | 8 个后正确弹出替换界面 | REL-002 |
| 8 | 广告流程 | 5 个点位正确触发，失败时正常降级不阻塞 | ADS-001~007 |
| 9 | 存档续玩 | 退出后重进可继续，进度一致 | SAVE-001~004 |
| 10 | 新手引导 | 3 分钟内完成，可跳过 | GUIDE-001~004 |

### 8.2 数值验收

| # | 验收项 | 通过标准 |
|---|--------|----------|
| 1 | 卡牌数量 | 51 张，编号与 GDD 第 5 章完全一致 |
| 2 | 卡牌定价合规 | 每张牌按 GDD 7.2 公式校验，价值/费用 ∈ [5.5, 7.5] |
| 3 | 本相自损合规 | 每张本相自损落在 GDD 7.3 对应费用区间 |

| 6 | 单局时长 | 10 局测试，平均 8–15 分钟 |

### 8.3 体验验收（玩家测试）

| # | 验收项 | 通过标准 |
