# 01 · 地图节点系统设计

**项目**：《聊斋美人》
**版本**：v1.0 ｜ **日期**：2026-10-22
**数值来源**：本文涉及的所有数值均引用《03 · GDD》第 8 章，不另行定义。

---

## 1. 设计目标

### 1.1 要解决的问题

现有线性三波结构的问题：

| 问题 | 后果 |
|------|------|
| 只有一条路径 | 每局体验完全相同，失去 Roguelike 的重玩价值 |
| 无法做取舍 | 玩家没有"这次走哪条路"的决策，缺一个核心乐趣点 |
| 资源曲线固定 | 无法形成"搏一把精英换强旧物"这类风险回报决策 |
| 地图无叙事 | 三层只是数值递增，没有"闯入更深的地方"的感觉 |

### 1.2 设计目标

1. **每局路线不同**：同一妖灵玩 10 局，至少 8 局路线不重复
2. **每次选择有权重**：不存在"闭眼选右边"的路径
3. **风险可自选**：玩家可以主动选择更高风险的路线换取更高回报
4. **单局时长可控**：三层共经过 17–21 个节点，8–15 分钟完成
5. **可读性强**：玩家看地图 3 秒内能做出决策

### 1.3 非目标

- 不做超大随机地图（不是《以撒》的房间迷宫）
- 不做地图记忆机制（不做迷雾、不做回头路）
- 不做联机同步地图

## 2. 地图整体结构

### 2.1 三层三卷

| 层 | 卷名 | 行数 | 每行节点 | 末尾 | 叙事 |
|----|------|------|----------|------|------|
| 第 1 层 | 凡尘 | 6 | 2–4 | Boss「姥姥」 | 兰若寺外院，尚在人间 |
| 第 2 层 | 幽冥 | 6 | 2–4 | Boss「鬼母」 | 阴司地界，规则开始失效 |
| 第 3 层 | 妖界 | 5 | 2–3 | Boss「树妖姥姥」 | 妖窟深处，直面本相 |

> 行数对应 GDD 8.1。每层结束后玩家可查看层间过渡页（显示本层统计：击杀数、获得旧物、剩余魂火）。

### 2.2 空间布局

地图采用**自下而上**的行进方向：

```
                    ┌─────────┐
       第 6 行      │  休息   │        ← Boss 前必为休息
                    └────┬────┘
                         │
       第 5 行      ┌────┴────┬────────┐
                    │  精英   │  事件  │
                    └────┬────┴───┬────┘
                         │        │
       第 4 行      ┌────┴────┐ ┌─┴──────┐
                    │  商店   │ │  战斗  │
                    └────┬────┘ └─┬──────┘
                         │        │
       第 3 行      ┌────┴────────┴───┐
                    │      战斗        │
                    └────────┬─────────┘
                             │
       第 2 行      ┌────────┴────────┐
                    │  战斗  │  事件  │
                    └────┬───┴───┬────┘
                         │       │
       第 1 行      ┌────┴───────┴────┐
                    │      战斗        │  ← 起点，必为战斗
                    └──────────────────┘
                             ↑
                         【入口】
```

### 2.3 坐标系统

| 概念 | 定义 |
|------|------|
| `layer` | 层索引，0–2 |
| `row` | 行索引，0 为最底（起点），向上递增 |
| `col` | 列索引，0 为最左 |
| `node_id` | `L{layer}_R{row}_C{col}`，如 `L0_R3_C1` |

## 3. 节点类型定义

### 3.1 六类节点

| 类型 | 代码 | 图标语义 | 玩家可获得 | 是否可跳过 |
|------|------|----------|------------|------------|
| **战斗** | `battle` | 剑 | 金、悟道点、情念三选一 | 否 |
| **精英** | `elite` | 骨 | 金（多）、悟道点（多）、旧物（必得）、情念 | 否 |
| **事件** | `event` | 面具 | 视事件而定（金/情念/旧物/祟） | 是（部分事件可离开） |
| **商店** | `shop` | 灯笼 | 花金购买情念/旧物/删牌/药水 | 是 |
| **休息** | `rest` | 烛火 | 回复魂火 或 移除 1 张牌（二选一） | 是 |
| **宝箱** | `treasure` | 匣 | 旧物 或 金 | 否 |

### 3.2 各类型详细规则

#### 3.2.1 战斗节点

| 项 | 规则 |
|----|------|
| 敌人数量 | 1–3 个，按层数决定（第 1 层 1–2，第 2 层 2–3，第 3 层 2–3） |
| 敌人来源 | 该层敌人池，按权重随机 |
| 奖励 | 金 10–18（GDD 7.7）+ 悟道点 5 + 情念三选一 |
| 可否放弃奖励 | 可（跳过拿牌） |
| 失败 | 魂火归零即本局结束 |

#### 3.2.2 精英节点

| 项 | 规则 |
|----|------|
| 敌人 | 该层精英池，固定 1 个 |
| 奖励 | 金 28–40 + 悟道点 12 + **旧物三选一（必得）** + 情念三选一 |
| 风险提示 | 进入前显示敌人名与血量上限 |
| 出现限制 | 不在前 2 行出现 |

#### 3.2.3 事件节点

| 项 | 规则 |
|----|------|
| 结构 | 文本描述 + 2–4 个选项 |
| 结果 | 每个选项有明确或模糊的结果提示 |
| 类型 | 增益型 / 交易型 / 风险型 / 叙事型 |
| 可跳过 | 部分事件有"离开"选项 |

**事件类型分布：**

| 类型 | 占比 | 示例 |
|------|------|------|
| 增益型（纯赚） | 30% | 拾得 1 张随机情念 |
| 交易型（有得有失） | 40% | 失去 8 魂火，获得 1 个随机旧物 |
| 风险型（赌） | 20% | 50% 概率获得传说旧物，50% 获得 2 张祟 |
| 叙事型（纯文本+小奖励） | 10% | 阅读一段故事，获得 10 金 |

#### 3.2.4 商店节点

| 项 | 规则 |
|----|------|
| 商品位 | 5 张情念 + 2 个旧物 + 1 次删牌服务 |
| 价格 | 见 GDD 7.7 |
| 刷新 | 不可刷新（一次性） |
| 离开 | 随时可离开 |

#### 3.2.5 休息节点

| 项 | 规则 |
|----|------|
| 选项 | 二选一：回复 30% 魂火上限（15 点）／ 移除 1 张牌 |
| 次数 | 每层至少 1 个，Boss 前必有 1 个 |
| 不可跳过 | 必须选择一项（可反复进出但只能选一次） |

#### 3.2.6 宝箱节点

| 项 | 规则 |
|----|------|
| 产出 | 70% 旧物 / 30% 金（40–60） |
| 特殊 | 有 15% 概率开出**诅咒旧物**（强力但带代价） |

## 4. 生成规则

### 4.1 生成流程

```
Step 1  确定层参数（行数、每行节点数范围）
Step 2  生成行与列骨架
Step 3  按权重填充节点类型
Step 4  应用硬性约束修正
Step 5  生成连线
Step 6  校验连通性
Step 7  校验路径多样性
```

### 4.2 每行节点数规则

| 行位置 | 节点数范围 | 说明 |
|--------|-----------|------|
| 第 1 行（起点） | 2–3 | 起始分支不宜过多 |
| 中间行 | 2–4 | 主要决策区 |
| 倒数第 2 行 | 2–3 | 收束 |
| 最后一行（Boss 前） | 1 | 单一休息点 |

> 单层节点总数控制在 **14–22 个**，玩家实际经过 6–8 个。

### 4.3 类型填充权重

| 类型 | 基础权重 | 修正 |
|------|----------|------|
| 战斗 | 45 | 第 1 行强制 100 |
| 事件 | 20 | — |
| 精英 | 12 | 前 2 行为 0；第 3 层 +5 |
| 商店 | 8 | 最后 2 行为 0；每层最多 1 个 |
| 休息 | 12 | 最后一行强制 100；每层至少 1 个 |
| 宝箱 | 3 | 第 1 层为 0 |

### 4.4 硬性约束（生成后必须校验）

| # | 约束 | 违反处理 |
|---|------|----------|
| C1 | 第 1 行全部为战斗 | 强制替换 |
| C2 | Boss 前一行只有 1 个休息节点 | 强制重建该行 |
| C3 | 精英不出现在前 2 行 | 替换为战斗 |
| C4 | 商店不出现在最后 2 行 | 替换为事件 |
| C5 | 每层休息节点 ≥ 1 | 随机将一个中间节点替换为休息 |
| C6 | 每层商店节点 = 1 | 不足则补，超出则替换 |
| C7 | 同一行相邻节点不得同类型（战斗除外） | 替换后一个 |
| C8 | 单个节点出边数 ∈ [1, 2] | 重建连线 |
| C9 | 单个节点入边数 ∈ [1, 2] | 重建连线 |
| C10 | 所有节点必须从起点可达 | 补连线 |
| C11 | 所有节点必须能通向 Boss | 补连线 |

### 4.5 连线规则

**基础算法（贪心 + 补全）：**

```
for each 节点 n in 第 i 行:
    随机选择 1~2 个 第 i+1 行 的节点作为后继
    优先选择 |col(n) - col(目标)| 最小的节点（避免长距离斜线）

补全阶段：
    for each 第 i+1 行 的节点 m:
        if m 无入边:
            找到第 i 行中 col 最接近的节点 n
            添加 n → m
```

**连线约束：**

| 约束 | 说明 |
|------|------|
| 不跨行 | 只能连接相邻两行 |
| 不回头 | 有向无环，单向向上 |
| 交叉最小化 | 相邻连线避免交叉（视觉可读性） |
| 出度 1–2 | 每个节点最多分叉成 2 条 |
| 入度 1–2 | 每个节点最多从 2 条路汇入 |

### 4.6 路径多样性校验

生成后计算**从起点到 Boss 的不同路径数量**。

| 层 | 最少路径数 | 说明 |
|----|-----------|------|
| 第 1 层 | ≥ 4 | 玩家至少有 4 种走法 |
| 第 2 层 | ≥ 4 | — |
| 第 3 层 | ≥ 3 | 行数少，要求略低 |

不足则重新生成（最多重试 10 次，仍不足则接受当前结果并记录日志）。

### 4.7 生成伪代码

```gdscript
func generate_layer(layer_idx: int) -> MapData:
    var cfg = LAYER_CONFIG[layer_idx]
    for attempt in 10:
        var rows = _build_skeleton(cfg)          # Step 2
        _fill_types(rows, cfg)                    # Step 3
        _apply_constraints(rows, cfg)             # Step 4（C1–C7）
        var ok = _build_edges(rows)               # Step 5（C8–C11）
        if not ok:
            continue
        if _count_paths(rows) < cfg.min_paths:    # Step 7
            continue
        return MapData.new(rows)
    return MapData.new(_last_valid_rows)          # 兜底
```

### 4.8 种子机制

| 项 | 规则 |
|----|------|
| 随机种子 | 每局开始时生成，用于复现 |
| 种子来源 | 时间戳 + 玩家 ID 哈希 |
| 用途 | 同种子生成完全相同的地图（便于测试与 bug 复现） |
| 展示 | 结算界面显示本局种子，玩家可分享 |

## 6. 数据结构

### 6.1 地图数据

```gdscript
class_name MapData
extends Resource

var seed: int = 0
var layer_index: int = 0
var rows: Array = []          # Array[Array[MapNode]]
var current_row: int = -1     # 玩家当前所在行，-1 表示未进入

func get_row(idx: int) -> Array:
    return rows[idx] if idx >= 0 and idx < rows.size() else []

func get_boss() -> MapNode:
    return rows[rows.size() - 1][0]
```

### 6.2 节点数据

```gdscript
class_name MapNode
extends Resource

var id: String = ""           # "L0_R3_C1"
var layer: int = 0
var row: int = 0
var col: int = 0
var type: String = "battle"   # battle/elite/event/shop/rest/treasure
var next_ids: Array = []      # 后继节点 id
var visited: bool = false
var locked: bool = false      # 当前不可进入
var payload: Dictionary = {}  # 事件 id / 敌人配置 / 商品列表
```

## 7. 交互与呈现

### 7.1 地图界面布局

```
┌──────────────────────────────────────┐
│  第 一层 · 凡尘        魂火 42/50    │
├──────────────────────────────────────┤
│                                      │
│            [休息]                     │  ← 可点击的节点高亮
│              │                       │
│      [精英]──┴──[事件]               │
│         │        │                   │
│                                      │
│      [商店]    [战斗]                │
│         │        │                   │
│          └───┬───┘                   │
│           [战斗]                     │  ← 当前位置
│                                      │
├──────────────────────────────────────┤
│  已走 4/6 行    旧物 3/8   金 128    │
└──────────────────────────────────────┘
```

### 7.2 可点击状态

| 状态 | 表现 |
|------|------|
| 可进入 | 正常显示，边框微亮 |
| 当前所在 | 高亮描边 + 呼吸动画 |
| 不可进入（未连通） | 灰暗，降低透明度至 40% |
| 已访问 | 打勾角标，不可再点 |
| Hover | 放大 1.05，显示 tooltip（节点类型 + 可能产出） |

### 7.3 交互流程

```
进入地图 → 只有一个起点可点 → 点击进入节点 → 完成节点内容
    → 返回地图 → 只能点当前节点连出的 1–2 个后继 → 循环
    → 到达最后一行 → 进入 Boss
```

### 7.4 决策辅助信息

每个节点必须让玩家在 **3 秒内**看懂：

| 显示项 | 说明 |
|--------|------|
| 图标 | 一眼识别类型 |
| 类型名 | 战斗/精英/事件/商店/休息/宝箱 |
| 风险提示 | 精英显示"高危"，宝箱显示"未知" |

**不显示**：具体敌人、事件内容、旧物名称（保留悬念）。

## 8. 与其它系统的衔接

### 8.1 与战斗系统

- 每次进入 `battle` / `elite` 节点触发一场战斗
- 战斗结束魂火**保留**（不回满），这是资源压力的来源
- 魂火归零 → 本局结束，回到局外

### 8.2 与旧物系统

| 节点 | 旧物产出 |
|------|----------|
| 精英 | 必得 1 个（三选一） |
| Boss | 必得 1 个（三选一，稀有度提升） |
| 宝箱 | 70% 概率 1 个 |
| 商店 | 可购买（2 个货位） |
| 事件 | 部分事件给予 |

### 8.3 与局外成长

- 地图不随局外解锁而变化
- 悟道点不影响地图生成
- 但解锁的新情念会进入战斗奖励池，间接影响路线选择（玩家会为了抽到某张牌而选更多战斗）

### 8.4 与叙事

每层开头有 1 段短文本（3–5 行），随层推进揭示聂小倩的心劫：

| 层 | 文本主题 |
|----|----------|
| 第 1 层 | 她是谁 —— 兰若寺的传闻 |
| 第 2 层 | 她为什么在这里 —— 树妖的控制 |
| 第 3 层 | 她想要什么 —— 被记得 |

## 9. 验收标准

| # | 验收项 | 通过标准 |
|---|--------|----------|
| 1 | 生成成功率 | 单次生成满足全部硬性约束的比例 ≥ 99%（含重试） |
| 2 | 路径多样性 | 同种子生成结果完全一致；100 次生成中不同地图 ≥ 95 种 |
| 3 | 连通性 | 1000 次生成中，无孤立节点、无死路 |
| 4 | 约束合规 | 1000 次生成中，C1–C11 违反次数 = 0 |
| 5 | 节点分布 | 单层各类型实际数量落在 GDD 8.2 的 min/max 区间内 |
| 6 | 决策时间 | 5 名测试者首次见到地图，平均决策时间 ≤ 5 秒 |
| 7 | 单局时长 | 10 局测试，平均 8–15 分钟 |
| 8 | 种子复现 | 同种子两次生成的地图数据 100% 一致 |
