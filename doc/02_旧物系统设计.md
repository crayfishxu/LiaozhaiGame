# 02 · 旧物系统设计

**项目**：《聊斋美人》
**版本**：v1.0 ｜ **日期**：2026-10-22
**数值来源**：基础参数引用《03 · GDD》第 9 章与 7.7 节经济表，不另行定义。

---

## 1. 设计目标

### 1.1 旧物在一局里承担什么

| 作用 | 说明 |
|------|------|
| **改变构筑方向** | 拿到「素纱」会倾向多打显相牌，「断剑」会倾向多打本相牌 |
| **提供随机叙事** | 每局旧物组合不同，形成"这局我靠什么赢"的记忆点 |
| **制造风险决策** | 诅咒旧物用明确代价换强力效果，让玩家主动做取舍 |
| **补偿运气** | 抽卡不顺时，旧物提供另一条强度曲线 |

### 1.2 设计红线

> **旧物不能替代构筑。** 一套烂牌组 + 神装旧物，必须打不过一套好牌组 + 普通旧物。

具体约束：

| 红线 | 说明 |
|------|------|
| 不提供"无脑数值碾压" | 最高单件增益不超过 +50% |
| 不做纯乘法叠加 | 多个增益之间用加法，避免指数爆炸 |
| 不消除核心张力 | 没有"免疫伤害"「无限心力」这类效果 |
| 不破坏翻面机制 | 旧物可以强化某一面，但不能让玩家"只打一面" |

## 2. 基础规则

### 2.1 核心参数

| 参数 | 数值 | 说明 |
|------|------|------|
| 同时持有上限 | **8** | 超出时必须放弃一个（不可出售） |
| 单局可获得总量 | 12–16 | 平均约 14 个，意味着要做 6 次以上取舍 |
| 同名唯一 | 是 | 全局不重复获得 |
| 出售 | 不可 | 只能通过放弃（不拾取）来"排除" |
| 触发顺序 | 按获取顺序 | 多个旧物同时触发时，先获得的先结算 |
| 跨局继承 | 否 | 每局清空 |

> 数据同步：《03 · GDD》9.1。

### 2.2 获取途径与概率

| 途径 | 数量 | 稀有度规则 |
|------|------|------------|
| **精英战胜利** | 必得 1（三选一） | 普通 40% / 稀有 45% / 史诗 15% |
| **Boss 战胜利** | 必得 1（三选一） | 稀有 50% / 史诗 40% / 传说 10% |
| **宝箱节点** | 1 个（70% 概率为旧物） | 普通 55% / 稀有 30% / 史诗 12% / 传说 3% |
| **商店** | 2 个货位 | 普通 50% / 稀有 32% / 史诗 14% / 传说 4% |
| **事件** | 视事件 | 由事件单独配置 |

**宝箱诅咒概率：** 每个宝箱有 **15%** 概率开出诅咒类旧物（见 5.5 节），此时不按上表稀有度抽取。

### 2.3 满槽处理

达到 8 个上限后，再获得旧物时弹出对比界面：

```
┌──────────────────────────────────────┐
│  旧物已满，选择放弃其一               │
├──────────────────────────────────────┤
│  [现有 8 个旧物列表]   [新旧物]      │
│   点击任意一个即可替换                 │
├──────────────────────────────────────┤
│           [ 放弃新旧物 ]              │
└──────────────────────────────────────┘
```

- 放弃的新旧物**不会**再出现（本局）
- 被替换的旧物**不会**回到池中

## 3. 效果类型分类

旧物按**触发时机**分为 6 类，便于程序实现与玩家理解。

| 类型 | 代码前缀 | 触发时机 | 举例 |
|------|----------|----------|------|
| **常驻型** | `PASSIVE_` | 一直生效，无需触发 | 攻击牌伤害 +1 |
| **战斗开始** | `ON_BATTLE_START_` | 每场战斗开始时 | 获得 4 点障 |
| **回合开始** | `ON_TURN_START_` | 每个玩家回合开始时 | 对全体造成 2 伤 |
| **出牌时** | `ON_CARD_PLAY_` | 每次打出牌时 | 首次出牌获得 1 障 |
| **受击时** | `ON_HURT_` | 受到伤害时 | 获得 1 点怨气 |
| **战斗结束** | `ON_BATTLE_END_` | 战斗胜利后 | 回复 2 点魂火 |

> 实现要求：所有触发必须走统一的事件总线，不允许在卡牌逻辑里硬编码旧物判断。

## 4. 稀有度与强度对应

| 稀有度 | 数量 | 占比 | 强度定位 | 设计约束 |
|--------|------|------|----------|----------|
| **普通** | 16 | 40% | 小幅强化，无条件 | 效果价值 ≤ 0.5 费卡 |
| **稀有** | 14 | 35% | 明显强化，有轻微限制 | 效果价值 ≈ 1 费卡 |
| **史诗** | 7 | 17.5% | 改变打法，有条件或代价 | 效果价值 ≈ 1.5 费卡 |
| **传说** | 3 | 7.5% | 定义一局的构筑核心 | 效果价值 ≈ 2.5 费卡，必带代价 |

> 数据同步：《03 · GDD》9.2。

**强度参照基准：** 1 费卡价值 ≈ 6 点伤害 ≈ 6 点障（GDD 7.1）。

## 6. 平衡规则

### 6.1 五条硬性约束

| # | 约束 | 校验方法 |
|---|------|----------|
| 1 | **单件增益 ≤ +50%** | 任何伤害/障/效率提升不超过 50%（E 类诅咒除外，但必有代价） |
| 2 | **同类增益加法叠加** | 三件 +25% 的旧物 = +75%，不是 ×1.95 |
| 3 | **不做无代价的乘法** | 禁止"伤害翻倍"类效果，除非配合明确代价 |
| 4 | **不做免疫/无限** | 禁止"免疫伤害""心力无限""必定胜利" |
| 5 | **保留翻面张力** | 强化单面的旧物，必须同时对另一面产生隐性抑制（如 A07 断剑强化本相但不加显相） |

### 6.2 增益上限保护

即使玩家凑齐所有增益，最终伤害倍率有上限：

```
最终伤害倍率上限 = 2.5 倍
超出部分直接截断
```

这是防止极端组合导致游戏失衡的兜底机制。

### 6.3 增益叠加顺序

```
基础伤害
  → + 固定加值（桃木剑+1、断剑+3）
  → × (1 + 百分比加值之和)  ← 加法而非连乘
  → 截断至 2.5 倍
  → × 祟弱系数 0.75（如有）
  → − 目标障值
```

> 与《03 · GDD》3.3 伤害公式兼容，此处为旧物修正的插入位置。

### 6.4 诅咒旧物的代价设计原则

| 原则 | 说明 |
|------|------|
| 代价必须**持续可感** | 每回合掉血、上限降低，而非一次性 |
| 代价必须**影响决策** | 让玩家在"这回合要不要用这张牌"上犹豫 |
| 代价必须**可补偿** | 存在某种方式抵消（如 E01 血契配 B02 干粮） |
| 不允许**纯负面** | 每个诅咒旧物都必须有玩家愿意接受的强力正面 |

### 6.5 旧物与卡池的协同表

| 旧物 | 强化方向 | 推荐搭配卡牌 |
|------|----------|--------------|
| A06 素纱 | 显相防御流 | G09 素衣、G10 薄纱、G11 障壁、Q24 白衣 |
| A07 断剑 | 本相爆发流 | G01 素手·本、G03 夜哭·本、Q08 蚀月·本 |
| A09 骨笛 | 叠毒流 | Q01 幽怨、Q02 蚀骨、Q06 长夜、Q23 兰若 |
| D03 静心符 + D04 缚魂铃 | 缠绕控制流 | Q13 情丝、Q15 千丝、Q20 丝网、Q17 索命 |
| A08 血玉 | 低血搏杀流 | G09 素衣·本（自损）、Q23 兰若·本（自损 8） |
| E02 枯骨 | 高费爆发流 | Q12 腐心（3 费）、Q23 兰若（3 费） |
| C08 无字碑 | 泛用 | 任何流派，但收益取决于牌组密度 |
| D06 双生镜 | 显相→本相转换 | 显相牌占比高的牌组 |

> **设计意图**：让玩家在拿到第一个旧物时，就产生"这局要往哪走"的方向感。

## 7. 数据结构

### 7.1 旧物定义

```gdscript
class_name RelicDef
extends Resource

var id: String = ""            # "A01"
var name: String = ""          # "半支金钗"
var rarity: String = "common"  # common/rare/epic/legendary
var category: String = "A"     # A/B/C/D/E
var trigger: String = ""       # ON_HURT / ON_TURN_START / PASSIVE ...
var desc: String = ""          # 玩家看到的描述
var cursed: bool = false
var params: Dictionary = {}    # 具体参数，如 {"grudge": 1}
```

### 7.2 事件总线接口

```gdscript
# Battle.gd 中触发，旧物系统统一监听
signal relic_trigger(trigger_name: String, ctx: Dictionary)

# 示例：受到伤害时
relic_trigger.emit("ON_HURT", {"damage": dmg, "source": "enemy"})

# 示例：回合开始
relic_trigger.emit("ON_TURN_START", {"turn": turn_count})
```

> **实现要求**：`Battle.gd` 内不得出现 `if has_relic("A01")` 这类硬编码判断，必须走总线。

### 7.3 持有列表

```gdscript
var relics: Array[String] = []   # 按获取顺序保存 id

func has_relic(id: String) -> bool:
    return relics.has(id)

func add_relic(id: String) -> bool:
    if relics.size() >= MAX_RELICS or relics.has(id):
        return false
    relics.append(id)
    return true
```
